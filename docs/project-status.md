# Состояние проекта «CRM-Агентство»

Дата фиксации: 29.09.2026  
Разработчик: Тынков Дмитрий  
Актуальное ТЗ: `Техническое_задание_ред_2.0.docx` (редакция 2.0 от 22.09.2026)

## Состояние требований и проектных материалов

ТЗ ред. 2.0 определяет MVP CRM рекламного агентства, обязательные каналы Telegram и веб-форму сайта, желательный канал VK, роли сотрудников/клиента/администратора, функциональные и нефункциональные требования и приемочные сценарии.

Лабораторная работа по актуализации UML выполнена на основе ТЗ и материалов ЛР № 2 и № 4. Use-case разделена на функциональные схемы с отдельными PNG-превью и PlantUML-исходниками; сводное изображение — [`uml-use-cases-all.png`](uml-use-cases-all.png), декомпозиция задач — в [`ЛР2_актуализация_UML_декомпозиция.md`](ЛР2_актуализация_UML_декомпозиция.md). Компонентная и последовательностная диаграммы находятся в [`uml-components.puml`](uml-components.puml) и [`uml-sequence-lead.puml`](uml-sequence-lead.puml). Старые отчеты ЛР № 2 и № 4 сохранены как исходные материалы.

Ключевые исправления UML: use-case разделена на небольшие схемы, связи актор–вариант использования показаны ассоциациями без наконечников стрелок; из модели удалены SMM-специалист и UC-10; UC-7 называется «Создание и отправка счета»; Avito и Posting Service удалены из компонентной схемы; добавлена веб-форма сайта, уточнены адаптеры и модули по архитектуре ТЗ. Последовательность приема лида уточнена для Telegram и сайта с проверкой дубликата.

## Реализация

В репозитории присутствует клиент Vue 3/Vite с демонстрационным экраном входа. Отправка формы показывает заглушку о будущем подключении сервера; реальная аутентификация, REST API, база данных и бизнес-сценарии пока отсутствуют. Серверный стек еще предстоит выбрать. Поэтому первый сквозной сценарий (обращение → клиент/лид → лента «Входящие») не реализован.

| Область | Статус |
|---|---|
| ТЗ ред. 2.0 | Актуально |
| Use-case, component и sequence UML | Актуализированы; use-case разбита на функциональные диаграммы с PNG-превью и PlantUML-исходниками |
| Декомпозиция и ближайший порядок работ | Подготовлены в документе лабораторной |
| Vue-клиент | Есть макет входа; серверной интеграции нет |
| Backend, PostgreSQL, Docker Compose | Не начаты |
| База данных и миграции | Не начаты |

| Остальные сценарии ТЗ, документация API и руководство | Не начаты |

## Ближайшая работа

Очередность реализации с зависимостями и критериями готовности приведена в документе лабораторной. Начальные задачи: выбрать серверный стек и описать контракты модулей; подготовить каркас API с PostgreSQL через Docker Compose; разработать схему данных. Затем реализовать Telegram и веб-форму, обработку дубликатов, поиск/создание клиента и лида и вывести новые обращения в «Входящие».
