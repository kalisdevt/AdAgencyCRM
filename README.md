# CRM-Агентство

CRM рекламного агентства: обращения из разных каналов собираются в единую ленту, по каждому автоматически заводятся клиент и лид, менеджер ведет переписку и сделку в одном окне.

Учебный мини-проект по дисциплине «Технологии создания и поддержки ПО». Требования — в [техническом задании](docs/Техническое_задание_ред_2.0.docx), текущее состояние — в [docs/project-status.md](docs/project-status.md).

## Что умеет система

Реализованы все обязательные требования ТЗ и большая часть желательных. Полный перечень со статусами — [docs/requirements-status.md](docs/requirements-status.md), проверка приемочных сценариев — [docs/acceptance-scenarios.md](docs/acceptance-scenarios.md), руководство по ролям — [docs/user-guide.md](docs/user-guide.md).

## Быстрый запуск

Нужен только Docker.

```bash
docker compose up --build
```

Откройте <http://localhost:8080>. При первом запуске применяются миграции и создаются демо-данные: сделки на всех стадиях воронки, задачи с макетом, счета, проект в работе и проект в архиве, отказы, расходы на кампании.

### Демо-учетные записи

Пароль у всех одинаковый: `demo12345` (меняется переменной `SEED_PASSWORD`). Данные только тестовые.

| Логин | Роль | Рабочий экран после входа | Разделы |
|---|---|---|---|
| `manager`, `manager2` | Менеджер по работе с клиентами | «Входящие» | Входящие, Проекты, Задачи, Уведомления |
| `head` | Руководитель отдела продаж | «Входящие» | То же + Отчеты (все, включая KPI) |
| `admin` | Администратор | «Входящие» | Все разделы + Пользователи, Справочники |
| `designer` | Дизайнер | «Задачи» | Задачи, Уведомления |
| `marketer` | Маркетолог | «Отчеты» | Отчеты (каналы, отказы), расходы, Справочники, Задачи |
| `director` | Директор | «Проекты» | Проекты, Отчеты (включая ожидаемую выручку) |
| `client` | Клиент (Ирина Волкова) | «Мои заказы» | Личный кабинет |

### Как показать основные сценарии

Пошаговая проверка семи приемочных сценариев ТЗ (с исходными условиями и способом независимой проверки результата) — в [docs/acceptance-scenarios.md](docs/acceptance-scenarios.md). Коротко:

1. `manager` → «Форма сайта» (или сообщение боту) → заявка появляется во «Входящих» как непрочитанная.
2. Во «Входящих» на вкладке «Задачи» сделки поставьте задачу дизайнеру; `designer` увидит уведомление и загрузит макет — он появится в сделке.
3. Укажите сумму, на вкладке «Счета» сформируйте PDF и отметьте оплату — сделка станет «Оплачено», появится проект.
4. В проекте отмечайте этапы; `client` увидит текущий этап в кабинете.
5. `head` → «Отчеты»: KPI менеджеров, каналы, причины отказа; любой отчет выгружается в CSV.

## Подключение Telegram-бота

Без токена система работает, но канал Telegram отключен. Чтобы принимать сообщения и отвечать на них:

1. Создайте тестового бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. В корне проекта создайте файл `.env` (в репозиторий не попадает):

   ```dotenv
   TELEGRAM_BOT_TOKEN=токен_бота
   TELEGRAM_POLLING=true
   ```

3. Перезапустите: `docker compose up -d`.

`TELEGRAM_POLLING=true` включает длинный опрос — публичный адрес не нужен. На сервере с HTTPS вместо опроса используется вебхук `POST /api/channels/telegram/webhook`: задайте `TELEGRAM_WEBHOOK_SECRET` и зарегистрируйте адрес методом `setWebhook` с тем же `secret_token`.

Сообщение боту появляется во «Входящих», ответ из панели диалога приходит клиенту в Telegram.

## Деплой и пайплайн

Проект разворачивается на Vercel (бесплатный план): клиент и API — контейнеры из `Dockerfile.vercel`, база — Neon PostgreSQL. Пошаговая инструкция: [docs/deploy-vercel.md](docs/deploy-vercel.md).

Пайплайн GitHub Actions ([.github/workflows/ci.yml](.github/workflows/ci.yml)) на каждый pull request и push в `master` выполняет ESLint, SAST (Semgrep), проверку «Master is merged», интеграционные тесты и сборку образов. После успешных проверок в `master` отдельный workflow ([deploy.yml](.github/workflows/deploy.yml)) разворачивает проект на Vercel.

Каждый pull request дополнительно проходит ИИ-ревью (Claude оставляет замечания к строкам). Настройка ревью и защиты ветки `master`: [docs/pull-requests.md](docs/pull-requests.md).

## Разработка

Нужны Node.js ≥ 22.18 и Docker (для PostgreSQL).

```bash
docker compose up -d db                 # PostgreSQL на localhost:5432

cd backend
cp .env.example .env
npm install
npm run seed                            # демо-пользователи, обращения и демо-сценарий
npm run dev                             # API: http://localhost:3000/api

cd ../frontend
npm install
npm run dev                             # клиент: http://localhost:5173
```

В режиме разработки Vite проксирует `/api` на `localhost:3000`. Миграции применяются автоматически при старте сервера.

### Тесты

```bash
cd backend && npm test
```

Линтер (ESLint) запускается в обеих частях командой `npm run lint`.

84 интеграционных теста покрывают все приемочные сценарии ТЗ. Тесты поднимают приложение и работают с отдельной базой `crm_test` на том же сервере PostgreSQL (создается автоматически), Telegram Bot API подменяется.

```
backend/

  src/
    modules/

      users/             учетные записи и роли
      channels/          адаптеры каналов: telegram, webform; точки входа каналов
      leads/             прием обращения, лента «Входящие», карточка клиента
      deals/             сделки: стадии, ответственный, кампания, причина отказа, ответ клиенту
      tasks/             задачи по сделкам, комментарии, файлы макетов
      files/             метаданные файлов, выдача с проверкой доступа
      notifications/     уведомления внутри системы
      invoices/          счета: PDF, сумма прописью, оплата, отправка в Telegram
      projects/          проекты и этапы, уведомление клиента
      portal/            личный кабинет клиента
      reports/           отчеты, расходы на кампании, CSV
      dictionaries/      справочники причин отказа и кампаний
    storage.js           файловое хранилище: диск или БД (Vercel)
    db/                  пул соединений, миграции, демо-данные и демо-сценарий
  assets/fonts/          шрифт DejaVu Sans для кириллицы в PDF
    middleware/          аутентификация, обработка ошибок
  test/                  интеграционные тесты
frontend/
  src/views/             экраны: вход, «Входящие», клиент, задачи, проекты, отчеты, кабинет клиента,
                         уведомления, пользователи, справочники, форма сайта
  src/components/        части экранов: задачи и счета сделки, список файлов
  src/styles/            стили: base.css (переменные, сброс), components.css (кнопки, поля),
                         и по файлу на экран — подключаются из .vue через <style scoped src>
docs/                    ТЗ, UML-диаграммы, декомпозиция, OpenAPI, состояние проекта, инструкция деплоя
.github/workflows/       пайплайн CI/CD
vercel.json              сервисы и маршрутизация на Vercel
scripts/                 резервное копирование и восстановление БД и файлов
```

Новый канал связи добавляется адаптером в `backend/src/modules/channels/` и регистрацией в `channels/index.js` — остальные модули работают с единым форматом события.

## Адаптивность

Интерфейс работает на телефонах, планшетах, ноутбуках и ПК (от 320 px):

| Ширина окна | Поведение |
|---|---|
| до 720 px (телефон) | меню — нижняя панель; «Входящие» показывают либо список, либо диалог; таблица пользователей превращается в карточки |
| 721–1080 px (планшет) | узкое боковое меню с иконками; «Входящие» в один столбец до 1000 px |
| от 1081 px (ноутбук, ПК) | полное боковое меню, список и диалог рядом |

## Резервное копирование

```bash
./scripts/backup.sh                      # копия БД в backups/crm-ДАТА.dump и файлов в crm-ДАТА.files.tar.gz
./scripts/restore.sh backups/файл.dump   # восстановление БД и файлов (заменяет текущие данные)
```

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DATABASE_URL` | Подключение к PostgreSQL | `postgres://crm:crm@localhost:5432/crm` |
| `JWT_SECRET` | Секрет подписи токенов; обязателен при `NODE_ENV=production` | — |
| `CORS_ORIGIN` | Адрес веб-интерфейса | `http://localhost:5173` |
| `TELEGRAM_BOT_TOKEN` | Токен бота; без него канал отключен | — |
| `TELEGRAM_POLLING` | `true` — получать сообщения длинным опросом | `false` |
| `TELEGRAM_WEBHOOK_SECRET` | Секрет вебхука Telegram; без него вебхук закрыт | — |
| `DATABASE_URL_UNPOOLED` | Прямое соединение для миграций, если `DATABASE_URL` ведет через пул соединений (Neon) | значение `DATABASE_URL` |
| `DB_POOL_MAX` | Размер пула соединений с БД | `10` |
| `TRUST_PROXY` | Настройка Express `trust proxy`: число прокси, `true` или список сетей | `loopback, uniquelocal` |
| `SEED_DEMO` | `true` — создать демо-данные при старте | `false` (в Docker Compose — `true`) |
| `SEED_PASSWORD` | Пароль демо-пользователей | `demo12345` |
| `FILE_STORAGE` | Где хранить содержимое файлов: `disk` — каталог, `db` — PostgreSQL (Vercel) | `disk` (в образе для Vercel — `db`) |
| `STORAGE_DIR` | Каталог файлового хранилища | `storage` (в Docker — том `files`) |
| `MAX_UPLOAD_MB` | Предельный размер загружаемого файла, МБ | `10` |
| `AGENCY_NAME`, `AGENCY_INN`, `AGENCY_KPP`, `AGENCY_ADDRESS`, `AGENCY_BANK`, `AGENCY_BIK`, `AGENCY_ACCOUNT`, `AGENCY_CORR_ACCOUNT`, `AGENCY_DIRECTOR` | Реквизиты агентства в счете | тестовые значения |
| `REPORT_TIMEZONE` | Часовой пояс, по которому отчеты считают даты | `Europe/Moscow` |

Секреты хранятся только в `.env`. При развертывании в сети перед nginx должен стоять HTTPS, а `JWT_SECRET` — заменен на случайное значение.
