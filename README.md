# CRM-Агентство

CRM рекламного агентства: обращения из разных каналов собираются в единую ленту, по каждому автоматически заводятся клиент и лид, менеджер ведет переписку и сделку в одном окне.

Учебный мини-проект по дисциплине «Технологии создания и поддержки ПО». Требования — в [техническом задании](docs/Техническое_задание_ред_2.0.docx), текущее состояние — в [docs/project-status.md](docs/project-status.md).

## Что работает сейчас

| Функция | Требование ТЗ |
|---|---|
| Прием сообщений Telegram-бота и заявок с веб-формы сайта (с UTM-метками) | FR-LEAD-01 |
| Защита от дубликатов при повторной доставке сообщения | п. 4.5 |
| Поиск клиента по ID в канале, телефону или e-mail; автоматическое создание клиента и лида | FR-LEAD-04 |
| Лента «Входящие»: фильтры по каналу, статусу, ответственному; выделение непрочитанных | FR-LEAD-03 |
| Карточка клиента: контакты, история сообщений, сделки, проекты | FR-LEAD-05 |
| Ответ клиенту из системы в Telegram | FR-LEAD-06 |
| Назначение ответственного менеджера | FR-LEAD-07 |
| Смена стадии сделки; «Отказ» — только с причиной из справочника | FR-DEAL-01, 03 |
| Вход по логину и паролю, роли, управление учетными записями | FR-ADM-01, п. 4.7 |

Задачи, проекты, счета, аналитика и личный кабинет клиента — следующие этапы; таблицы для них уже созданы миграциями.

## Стек

| Часть | Технологии |
|---|---|
| Сервер (`backend/`) | Node.js 24, Express 5, PostgreSQL 17 (`pg`, SQL-миграции), zod, JWT, bcrypt |
| Клиент (`frontend/`) | Vue 3 (Composition API), Vite 8, vue-router 4 |
| Окружение | Docker Compose: PostgreSQL, API, nginx с собранным клиентом |

## Быстрый запуск

Нужен только Docker.

```bash
docker compose up --build
```

Откройте <http://localhost:8080>. При первом запуске применяются миграции и создаются демо-данные.

### Демо-учетные записи

Пароль у всех одинаковый: `demo12345` (меняется переменной `SEED_PASSWORD`). Данные только тестовые.

| Логин | Роль | Что доступно сейчас |
|---|---|---|
| `manager`, `manager2` | Менеджер по работе с клиентами | «Входящие», карточки клиентов |
| `head` | Руководитель отдела продаж | «Входящие», карточки клиентов |
| `admin` | Администратор | То же + «Пользователи» |
| `designer`, `marketer`, `director` | Дизайнер, маркетолог, директор | Вход; разделы появятся на следующих этапах |

### Как показать сквозной сценарий

1. Войдите как `manager` — в ленте «Входящие» есть тестовые обращения.
2. В боковом меню откройте «Форма сайта» (страница `/request` имитирует сайт агентства) и отправьте заявку.
3. Вернитесь во «Входящие»: в течение 5 секунд заявка появится вверху ленты как непрочитанная, с каналом «Сайт» и кампанией из UTM-метки.
4. Откройте ее: назначьте ответственного, смените стадию; при выборе «Отказ» система потребует причину.
5. По имени клиента откройте карточку — контакты, сделки и история сообщений.

## Подключение Telegram-бота

Без токена система работает, но канал Telegram отключен. Чтобы принимать сообщения и отвечать на них:

1. Создайте тестового бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. В корне проекта создайте файл `.env` (в репозиторий не попадает):

   ```dotenv
   TELEGRAM_BOT_TOKEN=токен_бота
   TELEGRAM_POLLING=true
   ```

3. Перезапустите: `docker compose up -d`.

`TELEGRAM_POLLING=true` включает длинный опрос — публичный адрес не нужен. На сервере с HTTPS вместо опроса используется вебхук `POST /api/channels/telegram/webhook`: задайте `TELEGRAM_WEBHOOK_SECRET` и зарегистрируйте адрес методом `setWebhook` с тем же `secret_token`.

Сообщение боту появляется во «Входящих», ответ из панели диалога приходит клиенту в Telegram.

## Деплой и пайплайн

Проект разворачивается на Vercel (бесплатный план): клиент и API — контейнеры из `Dockerfile.vercel`, база — Neon PostgreSQL. Пошаговая инструкция: [docs/deploy-vercel.md](docs/deploy-vercel.md).

Пайплайн GitHub Actions ([.github/workflows/ci.yml](.github/workflows/ci.yml)) на каждый pull request и push в `master` выполняет ESLint, SAST (Semgrep), проверку «Master is merged», интеграционные тесты и сборку образов; после успешных проверок в `master` — деплой на Vercel.

Каждый pull request дополнительно проходит ИИ-ревью (Claude оставляет замечания к строкам). Настройка ревью и защиты ветки `master`: [docs/pull-requests.md](docs/pull-requests.md).

## Разработка

Нужны Node.js ≥ 22.18 и Docker (для PostgreSQL).

```bash
docker compose up -d db                 # PostgreSQL на localhost:5432

cd backend
cp .env.example .env
npm install
npm run seed                            # демо-пользователи и обращения
npm run dev                             # API: http://localhost:3000/api

cd ../frontend
npm install
npm run dev                             # клиент: http://localhost:5173
```

В режиме разработки Vite проксирует `/api` на `localhost:3000`. Миграции применяются автоматически при старте сервера.

### Тесты

```bash
cd backend && npm test
```

Линтер (ESLint) запускается в обеих частях командой `npm run lint`.

Интеграционные тесты поднимают приложение и работают с отдельной базой `crm_test` на том же сервере PostgreSQL (создается автоматически), Telegram Bot API подменяется.

## Структура

```
backend/
  migrations/            SQL-миграции (схема БД по п. 4.3 ТЗ)
  src/
    modules/
      auth/              вход, JWT
      users/             учетные записи и роли
      channels/          адаптеры каналов: telegram, webform; точки входа каналов
      leads/             прием обращения, лента «Входящие», карточка клиента
      deals/             сделки: стадии, ответственный, причина отказа, ответ клиенту
    db/                  пул соединений, миграции, демо-данные
    middleware/          аутентификация, обработка ошибок
  test/                  интеграционные тесты
frontend/
  src/views/             экраны: вход, «Входящие», карточка клиента, пользователи, форма сайта
  src/styles/            стили: base.css (переменные, сброс), components.css (кнопки, поля),
                         и по файлу на экран — подключаются из .vue через <style scoped src>
docs/                    ТЗ, UML-диаграммы, декомпозиция, OpenAPI, состояние проекта, инструкция деплоя
.github/workflows/       пайплайн CI/CD
vercel.json              сервисы и маршрутизация на Vercel
scripts/                 резервное копирование и восстановление БД
```

Новый канал связи добавляется адаптером в `backend/src/modules/channels/` и регистрацией в `channels/index.js` — остальные модули работают с единым форматом события.

## Адаптивность

Интерфейс работает на телефонах, планшетах, ноутбуках и ПК (от 320 px):

| Ширина окна | Поведение |
|---|---|
| до 720 px (телефон) | меню — нижняя панель; «Входящие» показывают либо список, либо диалог; таблица пользователей превращается в карточки |
| 721–1080 px (планшет) | узкое боковое меню с иконками; «Входящие» в один столбец до 1000 px |
| от 1081 px (ноутбук, ПК) | полное боковое меню, список и диалог рядом |

## API

Описание реализованных маршрутов в формате OpenAPI: [docs/openapi.yaml](docs/openapi.yaml). Ошибки возвращаются в едином виде:

```json
{ "error": { "code": "validation_error", "message": "Укажите телефон или почту для связи" } }
```

## Резервное копирование

```bash
./scripts/backup.sh                      # копия в backups/crm-ДАТА.dump
./scripts/restore.sh backups/файл.dump   # восстановление (заменяет текущие данные)
```

## Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DATABASE_URL` | Подключение к PostgreSQL | `postgres://crm:crm@localhost:5432/crm` |
| `JWT_SECRET` | Секрет подписи токенов; обязателен при `NODE_ENV=production` | — |
| `CORS_ORIGIN` | Адрес веб-интерфейса | `http://localhost:5173` |
| `TELEGRAM_BOT_TOKEN` | Токен бота; без него канал отключен | — |
| `TELEGRAM_POLLING` | `true` — получать сообщения длинным опросом | `false` |
| `TELEGRAM_WEBHOOK_SECRET` | Секрет вебхука Telegram; без него вебхук закрыт | — |
| `DATABASE_URL_UNPOOLED` | Прямое соединение для миграций, если `DATABASE_URL` ведет через пул соединений (Neon) | значение `DATABASE_URL` |
| `DB_POOL_MAX` | Размер пула соединений с БД | `10` |
| `TRUST_PROXY` | Настройка Express `trust proxy`: число прокси, `true` или список сетей | `loopback, uniquelocal` |
| `SEED_DEMO` | `true` — создать демо-данные при старте | `false` (в Docker Compose — `true`) |
| `SEED_PASSWORD` | Пароль демо-пользователей | `demo12345` |

Секреты хранятся только в `.env`. При развертывании в сети перед nginx должен стоять HTTPS, а `JWT_SECRET` — заменен на случайное значение.
